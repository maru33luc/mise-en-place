## ✦ Overview

**Mise en Place** is a dark, editorial kitchen management workspace inspired by a New York Michelin-starred restaurant. It compresses the operational layer of service into one focused, unhurried experience — from the walk-in to the pass.

## ◈ Product Tour

| | Area | What it does |
|:--:|---|---|
| 🏛️ | **Home** | Public, cinematic entry point with a direct path into the kitchen |
| 🔐 | **Authentication** | Register, sign in, and hold a JWT-backed in-memory session |
| 🍽️ | **Recipe Collection** | Create, edit, delete and inspect recipes with ingredients and difficulty |
| 📖 | **Recipe Detail** | Inspect a recipe, its base servings and ingredient quantities |
| 🧭 | **Daily Menu** | Drag recipes into **Starters**, **Mains** or **Desserts** for a service date |
| 🛒 | **Shopping List** | Aggregate menu ingredients and scale them to guest count |
| ⏱️ | **Prep List** | Track tasks, priorities, completion progress, per-task stopwatches |
| 📱 | **Responsive UI** | Layouts tuned for phone, tablet and desktop service stations |

## 🧰 Technology Stack

<div align="center">

**Frontend**

<img src="https://skillicons.dev/icons?i=angular,ts,sass,vitest&theme=dark" />

<br/>

<details open>
<summary><b>🖥️ Frontend details</b></summary>
<br/>

| Technology | Use |
|---|---|
| **Angular 22** | Standalone application architecture, lazy-loaded routes |
| **TypeScript 6** | Strictly typed application code |
| **Angular Signals** | Local and shared reactive state |
| **Angular Router** | Public/protected navigation and route guards |
| **Angular HttpClient** | API communication and interceptor pipeline |
| **Angular Forms** | Login, registration, recipe, menu and prep forms |
| **RxJS** | HTTP streams, error handling, lifecycle operators |
| **Vitest** | Component, service and utility tests |
| **ESLint + angular-eslint** | Static analysis and code quality |
| **Prettier** | Formatting for frontend source |
| **Native HTML5 DnD** | Menu builder interactions, zero CDK dependency |

</details>

<details open>
<summary><b>⚙️ Backend details</b></summary>
<br/>

| Technology | Use |
|---|---|
| **Node.js 20+** | Runtime |
| **Express 4** | HTTP server and route composition |
| **Zod** | Recipe request validation |
| **JSON Web Token** | Bearer token authentication |
| **bcryptjs** | Password hashing |
| **Helmet** | Security-related HTTP headers |
| **CORS** | Controlled frontend origin access |
| **express-rate-limit** | API request throttling |
| **In-memory models** | Fast local iteration without a database |

</details>

<details>
<summary><b>🔧 Engineering choices</b></summary>
<br/>

- Standalone Angular components instead of NgModules
- Signals for application state where a full state library isn't needed
- HTTP services kept separate from state stores
- Auth and error behavior centralized in interceptors
- Native browser drag & drop — a small dependency surface
- Strict configured port: the backend never silently switches ports

</details>

## 🚀 Getting Started

<table>
<tr>
<td width="33%" align="center">

**1️⃣ Install**
```bash
pnpm install
pnpm backend:install
pnpm frontend:install
```

</td>
<td width="33%" align="center">

**2️⃣ Configure**
```bash
cp backend/.env.example \
   backend/.env
```

Windows PowerShell:

```powershell
Copy-Item backend/.env.example backend/.env
```

</td>
<td width="33%" align="center">

**3️⃣ Run**
```bash
pnpm backend:start
pnpm frontend:start
```

</td>
</tr>
</table>

**Prerequisites:** Node.js **20+** · pnpm **9+** · a browser with modern JS + HTML5 drag-and-drop

```bash
node --version
pnpm --version
```

The backend reads `PORT` from `backend/.env` and binds to that exact port — no fallback. If you change it, update `frontend/src/environments/environment.ts` to match. If the port is taken, startup fails with `EADDRINUSE`.

<div align="center">

| Service | URL |
|---|---|
| 🔧 Backend | `http://localhost:3000` |
| 🎨 Frontend | `http://localhost:4200` |

<details open>
<summary><b>Public endpoints</b></summary>

| Method | Endpoint | Description |
|:--:|---|---|
| `GET` | `/api/health` | API health check |

</details>

<details open>
<summary><b>Authenticated endpoints</b></summary>
<br/>

Send the header: `Authorization: Bearer <token>`

| Method | Endpoint | Description |
|:--:|---|---|
| `GET` | `/api/auth/me` | Return the current user |
| `GET` | `/api/recipes` | List seed and user-owned recipes |
| `GET` | `/api/recipes/:id` | Get one recipe |
| `POST` | `/api/recipes` | Create a recipe |
| `PUT` | `/api/recipes/:id` | Update a user-owned recipe |
| `DELETE` | `/api/recipes/:id` | Delete a user-owned recipe |
| `GET` | `/api/menu` | List saved menus |
| `GET` | `/api/menu/:date` | Get a menu by ISO date |
| `PUT` | `/api/menu/:date` | Create or update a daily menu |
| `DELETE` | `/api/menu/:date` | Delete a daily menu |
| `GET` | `/api/prep-list` | List preparation tasks |
| `POST` | `/api/prep-list` | Create a preparation task |
| `PUT` | `/api/prep-list/:id` | Update task status or details |
| `DELETE` | `/api/prep-list/:id` | Delete a task |
| `DELETE` | `/api/prep-list/done` | Archive completed tasks |

</details>

## 🔐 Environment Variables

| Variable | Default | Purpose |
|---|---|---|
| `PORT` | `3000` | Required API listening port |
| `ALLOWED_ORIGIN` | `http://localhost:4200` | CORS frontend origin |
| `JWT_SECRET` | dev fallback | Token signing secret — set a strong value outside local dev |
| `JWT_EXPIRES` | `7d` | Token lifetime |
| `RATE_LIMIT_WINDOW_MS` | `60000` | Rate-limit window, in ms |
| `RATE_LIMIT_MAX` | `100` | Requests allowed per window |
| `BODY_LIMIT` | `10kb` | Maximum JSON body size |

> ⚠️ `backend/.env` is git-ignored. Never commit production secrets.

## 🧭 Current Scope & Next Steps

> The current phase intentionally uses **in-memory storage**. Restarting the backend clears users, custom recipes, menus and prep tasks — by design, for now.

- [ ] Backend integration tests and schemas for menu/prep payloads
- [ ] Advanced recipe filtering and smart unit conversion
- [ ] Persist timer elapsed time between updates
- [ ] Auto-derive prep tasks from menu recipes
- [ ] Durable storage for production and multi-instance deployment
- [ ] Expanded keyboard navigation and accessibility coverage
